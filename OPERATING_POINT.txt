--------------------------------------------------------------------------------
  2.  입력 — 2갈래
--------------------------------------------------------------------------------

  계측기가 60Hz 매 사이클로 33개 값을 준다:
      1~15차 고조파의 Re/Im (30개) + P + Q + Vrms

  이것을 60초 창(3600 사이클)으로 잘라 두 갈래로 만든다. 타깃 시점은
  **창 끝에서 6초 안쪽** 이다 (TARGET_LOOKAHEAD=360).

  [세밀 갈래]  (50, 600)   창의 뒤 10초를 60Hz 그대로

      ch 0~14    asinh(Re(ih_k) * 20)        k=1..15
      ch15~29    asinh(Im(ih_k) * 20)
      ch30       asinh(P / 100)
      ch31       asinh(Q / 100)
      ch32       (V - 222) / 10
      ch33       asinh(|I3|/|I1| * 50)       저항성 무리를 가르는 주 축 (0.2절)
      ch34       asinh(|I5|/|I1| * 50)
      ch35       asinh(|I2|/|I1| * 50)       ** 0 으로 죽어 있다 **
      ch36~37    P - 이동중앙값 (±0.5초 / ±2.5초)   리플·듀티 판별
      ch38~45    고조파 위상 불변량 phi_h - h*phi_1  (12.34)
      ch46       역률 P/(V*Irms)
      ch47       asinh(|I9|/|I3| * 50)
      ch48~49    다단 강하 전방 탭 3.0초 / 5.5초    (12.62)
      -------------------------------------------------------------
      ch50~57    홀수차 크기 채널 — **운영점이 안 쓴다** (소진 목록 2번, 12.80)
                 build_fine 은 58채널을 만들지만 모델은 앞 50개만 쓴다

      ** 짝수차 배제 ** (ZERO_EVEN_HARMONICS=True, 12.77)
      2~14차의 Re/Im 14채널 + ch35 가 **정확히 0** 이다. 짝수차가 계측
      인공물이라는 12.72 의 확정에 따른 것이고, 12.74 가 이것만으로 전이
      귀속을 21 -> 24/41 로 올렸다.

      ⚠ 다만 손실과 후처리는 짝수차를 **본다**. 4절 참조.

  [광역 갈래]  (12, 120)   창 전체 60초를 2Hz(0.5초 블록)로 요약

      블록 중앙값: P, Q, V, |I1|, |I3|, |I5|, |I2|
      P 의 블록 내 표준편차                 듀티 부하 판별
      |I3|/|I1|, |I2|/|I1|
      P - 10초 이동중앙값                  1.3절의 EMA 차를 창 안에서 대체
      계단 전이율                          블록간 |dP| 가 창 진폭 20% 를 넘는 비율

      ⚠ 요동 채널이 P 하나뿐이다. 홀수차 요동 채널은 없다 (12.121 참조).

  asinh 를 쓰는 이유: 판별 정보가 0.002~0.03 대역에 몰려 있는데 SMPS(0.9)와
  함께 z-score 하면 그 계단 구조가 뭉개진다. 측정으로 확인됐다 —
  asinh 88.2% > log 82.4% > 없음 70.6% (0.3절).


--------------------------------------------------------------------------------
  3.  모델 — 0.61M 파라미터
--------------------------------------------------------------------------------

  세밀 (50,600) --> 확장 conv 5층 --+
                                   +--> concat --> trunk --> 기기별 헤드 9개
  광역 (12,120) --> 확장 conv 3층 --+

  [세밀 인코더]  Conv1d(k=7) + GroupNorm + GELU, dilation 1/2/4/8/16
                 50 -> 64 -> 64 -> 128 -> 128 -> 128    수용영역 약 380사이클(6.3초)

  [광역 인코더]  Conv1d(k=5), dilation 1/2/4,  12 -> 32 -> 32 -> 64

  [trunk 에 들어가는 것]  (단순 평균 하나가 아니다)
      세밀 전역평균(128) + 세밀 전역최대(128) + 깊은층 타깃슬라이스(128)
      + 얕은층 타깃슬라이스 2개(64+64) + **원본 타깃 슬라이스(50)**
      + 광역 평균(64) + **원시 창 전력 통계 4개**
      -> Linear(→256) + GELU + Dropout(0.1) + Linear(256) + GELU

      원시 창 전력 통계 = [세밀P 최대, 세밀P 최소, 광역P 최대, 광역P 평균].
      conv 도 GroupNorm 도 안 거치고 헤드 직전에 붙는다 (12.9.8).

  [기기별 헤드]  9개, 파라미터 비공유. 각 13개 출력
      power(5) + state(5) + on(1) + plugged(1) + standby(1)

      전력은 **상태 수만큼** 낸다 (12.9.10). 한 헤드가 2자릿수 떨어진 두 상태를
      동시에 맡던 문제(오븐 팬 15W <-> 히터 1150W)를 그렇게 풀었다.

  [출력 조립]
      state  = 유효 상태만 남기고 마스킹 (기기별 상태수 2~5)
      p_raw  = sum_s softmax(state)_s * softplus(power_s)     OFF 상태는 제외
      P_hat  = sigmoid(on_logit) * p_raw                      on/off 게이팅

  [물리 프라이어]  prior_kappa = 8.0  (12.9.8)
      on_logit += logsigmoid(kappa * (창최대P - 그 기기의 최소ON전력))

      21.8W 창에 428W 핫플레이트는 물리적으로 불가능하다. 타깃 시점이 아니라
      **창 최대**를 쓴다 — 핫플은 2초 주기로 끊기므로 순시 전력으로 막으면
      휴지마다 미탐이 난다.

  ** 잔차 헤드는 없다 ** (3.3절). 닫힌 세계(9종 한정)라 표현할 대상이 없다.
  "설명 못 한 전력" 은 추론 시 산술로 낸다:  P관측 - sum(P_hat) - 대기 - 계측계


--------------------------------------------------------------------------------
  4.  학습 — 2단계
--------------------------------------------------------------------------------

  [1단계]  합성 사전학습            results/cnn_ovh.pt      약 30분

      캐시   cache/train60_ovh   독립 창 300,000개 (21.8GB)
             레시피 믹스 smps_hi_fix, 차수별 지터 진폭 sigma=0.20
      학습   300 epoch x 50,000창, 배치 512
      홀드   processed_data/holdout60_ze1   (sha 94e14306a27e276a)

      손실   power 1.0 (스케일 정규화 Huber, delta=0.1)
             state 0.3 / on 0.3 / plugged 0.1 / standby 0.1
             harm 0.1
             cons 0.0     <- 1단계에서는 거의 끈다 (3.3절)
             over 0.0

      ** 보존 손실을 1단계에서 올리면 안 된다 ** — 개별 전력 라벨보다 35~3000배
      강해 "합만 맞추는 해" 로 빠진다 (3.3절 정량 계산).

  [2단계]  실측 준지도 적응          results/adapt_ovh.pt    약 3분

      python -m src.run_adapt --init results/cnn_ovh.pt --cache cache/train60_ovh \
             --holdout-real test_8

      실측 창 9,627개 (11파일). test_8 은 적응에서 빼고 채점만 한다.

      L_adapt = w_cons * |sum P_hat + sum S_hat + noise - P관측|      w_cons 0.1
              + w_harm * ||sum P_hat*sig + 대기 + 계측계 - 관측고조파|| w_harm 4.0
              + w_hedge * 게이트 이진 엔트로피                          w_hedge 0.2
              + lam * L_전체(합성 replay)                              lam 0.5

      ** 기기별 라벨을 안 쓴다 **. 실측에 기기별 정답이 없다는 전제다 (4.2절).
      배분을 결정하는 항은 L_harm 하나뿐이다.

      학습률 3e-5 (1단계의 1/10). 합성 replay 는 파괴적 망각 방지.

      ⚠ 짝수차: 입력은 0 인데 L_harm 의 지문(sig)과 타깃(obs_harm)에는
      짝수차가 **들어 있다** (harm_odd_only 기본 False). 12.75 가 그 어긋남과
      단일 변수 재측정을 기록한다 — 빼면 유령이 줄지만 전이 귀속 최대값을
      잃어 채택 안 했다.

  [2] 저항 등가저항 정합      resistive_match         12.112, 12.117

      저항 부하는 니크롬선이라 P = V^2/R 이고 R 이 기기 고유값이다.

          포트 35.8   오븐 40.6   드라이기 54.3   핫플 101.8 옴
          (재현성 0.1~1.3%. 복합 실측에서도 격리값 대비 편차 중앙값 0.53%)

      창마다 G_필요 = (P관측 - 비저항예측 - 대기 - 계측) / V^2 를 구하고,
      저항 4종의 on/off 조합 16개 중 sum(1/R) 이 가장 가까운 것을 고른다.

      ** 개수는 안 바꾸고 맞바꿈만 한다 ** (규칙 18). 개수를 바꾸게 두면 정합기가
      없는 기기를 발명한다 — 제한 없이 돌렸을 때 test_9 유령이 3.94 -> 86.98W.

      드라이기 약풍은 반파 정류라 겉보기 102.6옴 으로 핫플과 겹친다. 그 둘만
      |I2|/|I1| > 0.15 로 가른다.

  [2b] 전력 스냅              resistive_match(snap)   12.117    ** 기본 켜짐 **

      조합이 이미 맞는 창(best == cur)에서는 예전에 아무것도 안 했다. 그런데
      **조합은 맞고 전력이 틀린 창** 이 있다 — 오븐이 옳게 켜져 있는데 780W
      (V^2/R=1130W)로 모자라고 그 차이가 게이트 0.26 을 타고 포트로 샜다.
      이제 그 창에서도 V^2/R 로 맞춘다. 개수도 신원도 안 바뀐다.

          시드 4개에서  유령 8.98 -> 5.23W,  실행 간 폭 6.05 -> 4.15W
                       잔차 10.15 -> 7.30W,  F1 과 전이 귀속은 불변

--------------------------------------------------------------------------------
  7.  알려진 한계 — 무엇이 왜 안 되는가
--------------------------------------------------------------------------------

  [프로젝터 <-> 충전기]   이 계측·이 창에서는 원리적 한계에 가깝다

      전력대가 38% 겹친다 (충전기 15~76W 가 프로젝터 45.9~48.8W 를 덮는다).
      총 SMPS 전력만으로 조합이 유일해지는 구간이 22% 뿐이다.
      고조파는 격리에서 위상 d' 12.99 인데 **중첩에서 0.4 로 죽는다**.
      차수를 올려도 안 된다 — d' 가 3차 12.99 에서 15차 0.01 로 단조 하강한다.

  [미니PC]   혼동이 아니라 검출 문제

      전력대 겹침이 3.7% 뿐이라 크기로는 갈린다. 문제는 1kW 급 부하 아래에서
      15W 를 찾는 것이다 (0.7절의 오차 전가). 경쟁 SMPS 가 있으면 재현율이
      98% 에서 30~67% 로 떨어진다 (12.81.2).

  [오븐]   모델이 아니라 채점의 문제

      라벨은 사람이 스위치를 켠 세션 전체인데 모델은 히터 통전을 예측한다.
      재현율의 천장이 0.607 이고 실측 0.528 은 그 천장의 87% 다.
      run_gate_check --session-merge 로 양쪽을 세션으로 묶어 재면 0.925 (12.119).

  [에어컨·선풍기]   지금 재고 있지 않다

      라벨 있는 11파일 중 등장 0개다. 봉인 파일 test.csv 에만 에어컨이 있는데
      거기서 20분 내내 130W 씩 낮게 읽는다 (잔차 92W, 13파일 중 최악).

  [CNN 의 한계인가]   아니다

      같은 가중치로 합성 홀드아웃에서는 프로젝터 0.990 / 충전기 0.998 /
      미니PC 0.948 이다. 구조가 못 하는 게 아니라 도메인 격차다.
      용량 가설도 기각됐다 — 폭 2배(0.6M -> 2.3M)로 MAE 가 더 나빠졌다 (12.9.11).

      12.112  저항 등가저항 정합 후처리   저항 전용 파일 F1 0.268 -> 0.782
      12.117  전력 스냅 후처리           유령 8.98 -> 5.23W

      -> (a) 라벨 정의를 고치거나  (b) 물리 제약을 추론 뒤에 걸거나

  반대로 **특징 추가와 손실 수정은 24번 시도해 0번 성공했다**
  (소진 목록 18개 + 2026-08-31 세션의 6개).

  이유는 12.87.3 이 설명한다 — 정보가 부족한 게 아니라 **배분이 미결정**이다.
  총합(L_cons)과 고조파(L_harm)를 둘 다 만족시키는 배분이 여러 개이고,
  관측 한 순간으로는 그중 하나를 고를 근거가 없다.

  ** 그래서 새 제안이 오면 먼저 물을 것 **
      - 이것이 라벨 정의 문제인가?
      - 이것을 물리 상수로 추론 뒤에 강제할 수 있는가?
      - 그 양이 기기 고유값인가, 아니면 다른 부하가 켜지면 변하는가?
        (후자면 후처리로 안 된다 — 요동 정합이 그래서 실패했다)
