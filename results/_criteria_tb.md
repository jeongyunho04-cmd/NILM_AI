# 판정 기준 — `L_swap` 의 고조파 동점깨기 (12.165.6 의 A'')

**결과보다 먼저 적는다 (규칙 22). 시드 3개 (규칙 50).**

## 왜
`L_swap` 은 허용오차(`swap_tol` 0.02) 안에서 **컨덕턴스 argmin** 으로 조합을
고른다. 그런데 컨덕턴스가 같으면 **전력도 같다** (12.165.5):
```
포트                1377 W    h3/h1 0.37%
드라이기강 + 핫플      1392 W    h3/h1 2.14%     15W(1.1%) 차이
```
전력 축에서는 정보가 0 이라 어느 쪽이 이길지가 반올림에 달린다. 실측에서
그것이 포트 오탐으로 나왔다 — 장소B test_15 정밀도 1.00 -> 0.84, test_18 -> 0.83,
오탐 창은 전부 드라이기+핫플이 켜진 1500W 창이다.

남은 축퇴는 **2쌍뿐**이고 (나머지 6쌍은 `ch50` 반파 채널이 이미 가른다)
둘 다 h3 로 5.8배 / 3.2배 갈린다.

## 처방
tol 안의 후보 전부를 모아, **관측 고조파 잔차에 가장 가까운 조합**을 고른다.
```
h_res = obs_harm − (저항 아닌 기기 예측 + idle·standby_sig + 계측계)
점수  = mean_over(h∈{3,5,7}) |조합 예측 − h_res| / harm_scale
```
**h1 은 안 쓴다** — 12.156 이 `L_harm` 판별의 97.6%가 h1 이라고 쟀고, 여기서
축퇴인 축이 바로 그 h1 이다. `--swap-tiebreak h3 --swap-tb-orders 3,5,7`.

## 자
```
adapt_h2_s{0,1,2}    대조   tiebreak off        (있음)
adapt_tb_s{0,1,2}    처방   tiebreak h3         1단계는 cnn_h2.pt 로 같다
```
2단계만 다르다. **한 변수만 바뀐다.**

## ① 인과 — 오탐이 줄어야 한다
```
포트 정밀도 (장소B, 3시드 중앙)
   test_15  0.84 -> **0.97 이상**
   test_18  0.83 -> **0.97 이상**
안 움직이면 h_res 가 너무 더러운 것이다 (SMPS 예측 오차가 h3 을 덮는다).
```

## ② 사는 것
```
장소B 포트 F1   0.935 -> **0.98 이상**   (hwO 대조 0.995)
장소A 포트 F1   0.866 -> **0.92 이상**   (hwO 대조 0.897)
로그의 "동점 N개" 가 1 보다 커야 한다 — 1.0 이면 고를 것이 없었다는 뜻이다
```

## ③ 지켜야 하는 것 (3시드 중앙)
```
장소B  드라이기 0.932 · 오븐유령 12.1W · 핫플(병합) 0.901 · 잔차 14.66
장소A  미니PC 0.868 · 드라이기 0.873 · 전체F1(병합) 0.912 · 유령 3.32W
```

## 미리 적어 두는 위험
```
- `h_res` 는 모델 자신의 비저항 예측을 뺀 값이다. SMPS 의 h3 이 크므로
  (프로젝터 47W 에서 |I3| 0.2A) 그 예측이 20% 틀리면 0.04A 오차인데,
  가르려는 두 조합의 차이가 0.115A 다. 신호 대 잡음 ~3배 — 넉넉하지 않다.
  **실패 모양**: ①이 안 움직이고 드라이기까지 같이 나빠진다.
- h3 만이 아니라 5,7 을 같이 쓴다. 12.135 가 높은 차수는 신호가 아니라
  모델오차라고 쟀으므로(τ h1 0.079 vs h14 1.696) 3,5,7 로 끊었다.
  그래도 h5·h7 이 잡음이면 h3 단독이 나을 수 있다 — 그때는 `--swap-tb-orders 3`.
- 동점깨기는 **후보가 여럿일 때만** 다르다. 스모크에서 평균 1.68개였으니
  일은 있다. 만약 실전에서 1.0 에 가까우면 항이 아무것도 안 한다.
```

# 추가 — `mag` (크기 비교, h3 단독) (12.165.7)

**`h3`(복소)은 반증됐다. 결과보다 먼저 적는다.**

## 무엇이 틀렸나
복소 거리는 `harm_offset`(12.148 의 Norton 보정, 창마다 다른 복소 오프셋)이
`h_res` 에서 안 빠져 **위상이 돌아가 있다.** test_16 의 h3 에서:
```
|h_res| 0.105   |포트| 0.024   |드+핫| 0.131
크기로는 드+핫이 맞는데  복소 거리는 |A−h| 0.098 < |B−h| 0.220 -> 포트를 고른다
```
결과: 장소B 포트 0.935 -> 0.853, 핫플 0.901 -> 0.701, 전체F1 0.861 -> 0.809.

## 처방
차수별 **크기**만 비교한다 (공통 위상 회전에 면역). 차수는 **h3 하나**:
```
차수   ||A|−|h||   ||B|−|h||   드+핫(정답) 선택률
h3       0.081       0.026       **89~100%**
h5       0.122       0.113          100%
h7       0.082       0.139        **0%**   <- 오히려 틀린 쪽을 고른다
```
12.135 가 높은 차수는 신호가 아니라 모델오차라고 쟀다. `--swap-tb-orders 3`.

## 자
```
adapt_h2_s{0,1,2}   대조   tiebreak off        (있음)
adapt_tb_s{0,1,2}   반증   tiebreak h3 (복소)   (있음)
adapt_tb2_s{0,1,2}  처방   tiebreak mag, 차수 3
```

## 판정 (①②③ 는 위와 같다, 대조만 갱신)
```
① 포트 정밀도 장소B test_15 0.84 / test_18 0.83 -> **0.97 이상**
② 장소B 포트 F1 0.935 -> **0.98 이상** | 장소A 포트 0.866 -> 0.92 이상
③ 장소B 드라이기 0.932 · 핫플(병합) 0.901 · 전체F1 0.861 · 유령 12.1W
   장소A 미니PC 0.868 · 전체F1(병합) 0.912
   **`h3`(복소)이 깨뜨린 것들이 돌아와야 한다** — 특히 핫플 0.701 -> 0.90 대
```

## 미리 적어 두는 위험
```
- 사용자 지적: "h3 로 구분하면 SMPS 가 같이 켜져 있을 때 영향이 있지 않나."
  쟀다. 장소 B 에서 빼야 할 SMPS 의 h3 이 0.37~0.44A 로 **신호(0.12A)의
  3~4배**다. 판정선까지의 여유를 SMPS 20% 오차의 방향 성분과 비교하면
  **2.0~3.1배** 뿐이다 (장소 A test_11 은 16.6배). SMPS 예측이 50% 틀리는
  창에서는 뒤집힐 수 있다. **그것이 이 처방의 상한이다.**
- 크기 비교는 위상 정보를 버린다. 위상이 옳게 정렬된 창에서는 복소가 더
  나을 수 있는데, 그러려면 `harm_offset` 을 `h_res` 에서도 빼야 한다.
  이번에는 안 한다 (한 번에 하나).
```
