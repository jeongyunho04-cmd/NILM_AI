# 판정 기준 — 미니PC 참값을 손실에 넣는다 (12.159)

**결과보다 먼저 적는다 (규칙 22). 시드 3개 (규칙 50).**

## 왜
사용자 정보: **`test_14`~`test_18` 의 미니PC 는 마우스 고장으로 IDLE 전용이다.**
`REFERENCE_W` 가 미니PC 를 뺀 이유(폭/중앙 1.162)는 IDLE(9.54/10.18/9.90W,
**폭/중앙 0.065**)과 ACTIVE(16.27/18.75/21.64W, 0.286)를 합쳐서다. IDLE 만
보면 채택 문턱 0.10 을 통과한다. 신호로 교차 확인됨 — 계단 +10.1~+14.7W.

진단 (12.159.1):
```
미니PC p_raw (게이트 곱하기 전)   장소 A 7.39W   **장소 B 0.64W**   참값 9.90W
게이트 σ 중앙                    장소 A 0.982   **장소 B 0.475**
```
**장소 B 에서 모델은 미니PC 를 0.6W 짜리로 안다** — 크기 자체가 틀렸다.
게이트는 문턱 근처라 `σ` 를 곱하는 항이 잘 든다 (규칙 51 의 자).

## 자
```
hwO   대조   w_pref = 0                          (있음, seed 0/1/2)
hwP   처방   w_pref > 0, 미니PC 참값 9.90W 를
             **test_14~18 창에만** 건다 (창별 마스크)
```
⚠ 전역으로 걸면 안 된다 — 장소 A 의 `test_13` 에 +27.3W 계단(ACTIVE)이 있다.

## 미리 적어 두는 위험
```
- `w_pref` 는 `p_raw` 만 고치고 게이트는 detach 된 마스크로만 쓴다 (12.145).
  게이트가 안 따라오면 P 는 그대로다. 그때는 게이트 쪽 처방이 따로 필요하다.
- 미니PC p_raw 가 9.9W 로 오르면 그 몫이 다른 SMPS 에서 빠져야 한다.
  프로젝터(현재 +16.4W 과대)가 후보이고 그러면 좋다. 충전기가 빠지면 나쁘다.
- w_pref 값을 못 정했다. 12.144.2 가 `>=0.02` 면 최적이 옮겨지고 포화한다고
  쟀지만 그것은 프로젝터(46.9W) 기준이다. 미니PC 는 9.9W 라 규모가 5배 작다.
  0.02 로 시작하고 안 들으면 훑는다 (훑기를 기록한다).
```
