# 판정 기준 — `on ⊂ plugged` 를 로짓에 강제한다 (12.164.9 의 처방 a)

**결과보다 먼저 적는다 (규칙 22). 시드 3개 (규칙 50).**

## 처방
```python
parts["impl"] = F.relu(out["on_logit"] - out["plugged_logit"]).mean()
```
9종 전부에 건다 — 합성 30만 창에서 `on=1 & plugged=0` 은 **9종 모두 0건**이라
포함관계가 보편적이다 (꽂히지 않은 기기가 켜질 수는 없다). 로짓에 직접 거는
이유는 규칙 51 — σ 를 곱하면 포화된 게이트에 안 닿는다. 힌지라
`plugged_logit >= on_logit` 인 창은 정확히 0 이고 건드리지 않는다.

## 자
```
hwZ    대조   새 1단계(cnn_hwY) + 옛 sig, w_impl=0        (있음, seed 0/1/2)
im2    처방   같은 것 + w_impl 2.0                        seed 0/1/2
im05   민감도 같은 것 + w_impl 0.5                        seed 0 만
```
2단계만 바꾼다. 1단계(`cnn_hwY.pt`)는 그대로 쓴다.

## 시작점에서 잰 것
```
위반율 (창×기기 중 on_logit > plugged_logit)   19.89%
L_impl 값                                     0.5133
```

## ① 인과 — 위반이 실제로 줄어야 한다
```
위반율 19.89% -> **5% 미만**
안 줄면 가중이 모자란 것이다 (그때는 w 를 올린다, 처방이 틀린 게 아니다)
```

## ② 사는 것 — 이것이 목적이다
```
장소B 드라이기 F1   0.655 -> **0.90 이상**       (hwO 대조 0.945)
장소B 오븐 유령W    134   -> **20 미만**          (hwO 대조 1.1, 오븐 없는 장소다)
장소B 전체F1        0.787 -> **0.84 이상**        (hwO 대조 0.853)
**시드 3개가 다 그래야 한다.** 다중해를 없애는 것이 이 처방의 논리다 —
2/3 만 되면 12.164 와 같은 상태이고 채택하지 않는다.
```

## ③ 지켜야 하는 것 — 12.164 가 벌어 놓은 것
```
오븐 FAN_LIGHT standby (test_4 조용한 창)  15.56W 가 **12~16W 안에** 남아야
장소A 전체F1 0.859 · 포트 0.960 · 미니PC 0.799 · 유령 3.50W
```

## ④ 실패 모양을 미리 적는다 — **어느 쪽이 양보하는가**
제약은 두 가지로 만족될 수 있다:
```
(가) on 을 내린다      <- 원하는 것. 장소 B 에 오븐은 없다
(나) plugged 를 올린다 <- 원치 않는 것. 12.164 가 벌어 놓은 신호를 도로 지운다
```
**(나) 를 감시하는 자**: `run_oven_idle_probe` 의 `idle[oven]`, 오븐이 없는
test_5~8 에서 hwZ 는 0.00~0.06 이다. 이것이 **0.2 를 넘으면 (나) 로 간 것**이고,
그러면 다음 수는 `plugged_logit` 을 detach 해 `on` 쪽만 미는 판이다.

## 미리 적어 두는 다른 위험
```
- 9종 전부에 걸었다. 미니PC·프로젝터처럼 plugged 가 늘 1 인 기기에서는 항이
  거의 0 이어야 한다 — 아니라면 그 기기의 두 머리가 이미 어긋나 있다는 뜻이고,
  그건 그 자체로 새 발견이다.
- w=2.0 은 L_swap 과 같은 값으로 고른 것이다 (둘 다 로짓 공간 제약이고 크기가
  비슷하다: swap 1.1~2.6, impl 0.51). 근거는 그뿐이라 im05 로 민감도를 본다.
```

# 추가 — `impl_side=on` (12.164.11)

**`both` 는 반증됐다. 결과보다 먼저 적는다.**

## 무엇이 일어났나
`w_impl=2.0, both` 는 위반을 19.89% -> 0.72% 로 없앴는데 **장소 B 유령이 129W
그대로**다. 모델이 `on` 을 내리는 대신 **`plugged` 를 올려서** 만족시켰다:
```
장소 B 오븐 발화 창의 σ(plugged)     hwZ 0.019~0.032  ->  im2 0.941~0.984
장소 B 나머지 창의 σ(plugged)        hwZ 0.001~0.011  ->  im2 0.088~0.926
```
내가 미리 적은 감시자(④)는 **틀린 장소를 보고 있었다** — 오븐 없는 파일로
test_5~8(장소 A)을 골랐는데 유령은 장소 B 에 있다. 그래서 (나)를 놓칠 뻔했다.
장소 A 에서는 실제로 (나)가 안 일어났다 (`idle[oven]` 0.006~0.133 유지).

## 처방
`relu(on_logit − plugged_logit.detach())` — **`on` 쪽만 민다.** 근거는
장소 B 에서 `σ(plugged)≈0.02` 쪽이 **옳다**는 것이다 (그 장소에 오븐은 없다).
틀린 것은 `on` 이므로 기울기를 그쪽에만 준다.

## 자
```
hwZ    대조    w_impl=0                       (있음)
im2    반증됨   w_impl=2.0 both               (있음)
ion2   처방    w_impl=2.0 impl_side=on        seed 0/1/2
```

## 판정 (②③ 는 위와 같다)
```
② 장소B 드라이기 0.640 -> **0.90 이상**, 오븐 유령 129 -> **20W 미만**, 시드 3개 전부
③ 오븐 FAN_LIGHT standby 12~16W 유지 | 장소A 전체F1 0.864 · 유령 2.21W 유지
④ 장소 **B** 의 σ(plugged)[oven] 이 0.1 아래로 남아야 한다 (이번엔 옳은 장소를 본다)
⑤ 위반율은 5% 아래로
```

## 미리 적어 두는 위험
```
- detach 하면 `plugged` 가 아무 제약도 안 받는다. `plugged` 가 스스로 0 으로
  가면 `on` 도 따라 눌려 오븐을 아예 못 켜게 될 수 있다 — 장소 A 오븐 F1
  0.636 이 그 자다. 크게 떨어지면 과제약이다.
- 이것도 안 들으면 원인은 함의 제약이 아니다. `L_res`/`L_swap` 이 드라이기
  강풍보다 오븐+포트를 **실제로 더 싸게 본다**는 뜻이고, 그때는 12.164 를
  접고 `RESISTIVE_OHM`/`swap_tol` 쪽을 봐야 한다.
```
