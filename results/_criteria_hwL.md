# 판정 기준 — `L_swap`: resistive_match 를 **로짓 감독**으로 (12.158)

**결과보다 먼저 적는다 (규칙 22). 시드 3개로 판정한다 (규칙 50).**

## 왜 이 형태인가
12.157.4b 가 확정했다 — `σ` 를 곱해 거는 항은 게이트가 바닥이면 안 닿는다.
효과가 처방 전 게이트로 **완전히 예측**됐다 (포트 σ중앙 0.0344 -> +0.563,
핫플 0.0033 -> +0.009, 드라이기 강풍 0.0001 -> −0.011).
그래서 `σ` 를 안 거치고 **로짓에 직접** 건다.

```
G_필요 = (관측 P − 비저항·미고정 예측 − 대기 − 동반 − 계측) / V²
best   = argmin_{|조합|=현재개수} |Σ_{i∈조합} 1/R_i − G_필요|
L_swap = BCE(on_logit[저항열], best)   단  best≠현재  이고  상대오차 ≤ tol 인 창만
```
12.112 의 두 제한을 그대로 가져온다: **개수는 안 바꾸고 맞바꿈만**(안 그러면
없는 기기를 발명한다 — test_9 유령 3.94 -> 86.98W), **tol 밖은 안 건드린다**.
`best==현재` 인 창을 빼는 이유: 거기서 BCE 는 "지금 결정을 더 확신해라" 인데
그 결정이 틀렸으면 굳는다 (12.122.2 의 *"최소가 오답 쪽에 있다"*).

```

## 미리 적어 두는 위험
```
- 후처리는 추론 때 한 번 도는데 손실은 1,000 스텝을 민다. 틀린 조합을 반복해
  가르치면 굳는다. 그래서 tol 을 0.02 로 좁게 잡고 best≠현재 인 창만 건다.
- 개수 고정이 겨냥을 막을 수 있다. 드라이기 강풍이 꺼지고 오븐이 켜진 것은
  **맞바꿈**이라 개수가 같다 — 그래서 이 제한으로도 닿는다. 핫플은 확인 안 됐다.
- `L_swap` 이 감독하는 창이 너무 적으면(맞바꿈이 드물면) 아무 일도 안 일어난다.
  **감독 창 비율을 로그에 찍어서 먼저 볼 것.**
- w_swap 을 못 정했다. BCE 스케일이 헤지 항과 비슷하므로 0.2 로 시작한다.
  안 들으면 올린다 (그때는 훑기를 기록한다).
