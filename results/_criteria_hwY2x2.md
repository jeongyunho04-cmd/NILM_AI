# 판정 기준 — 장소 B 붕괴의 원인을 가른다 (12.164.6)

**결과보다 먼저 적는다 (규칙 22).**

## 무엇이 일어났나
`gt_plugged` 재정의(12.164)로 **인과는 통과**했는데(오븐 FAN_LIGHT standby
9.25 -> 15.56W, 참값 14.2) **장소 B 가 무너졌다**: 드라이기 0.945 -> 0.655,
오븐 유령 1.1 -> 128.6W. 오븐이 없는 장소에서 드라이기 강풍(~930W)을
**오븐 660W + 포트 270W** 로 맞바꾼다. 반파 관문이 닫힌 창에서만 그런다.

## 나는 한 번에 셋을 바꿨다 — 이미 하나는 걷어냈다
```
(1) 1단계 라벨      cache/train60_hwY 로 학습한 cnn_hwY.pt
(2) 2단계 replay    적응의 --cache 도 train60_hwY (λ=0.5 로 감독 손실을 계속 건다)
(3) standby_sig     --standby-operating session
```
`hwZ` = (1)+(2), (3) 없음 -> 유령 134W. **(3) 은 무죄.**

## 자 (2×2, 시드 3개)
```
                     1단계 라벨     2단계 replay 캐시     결과
hwO      대조           옛              옛              유령   1.1W  드라이기 0.945
hwZ      처방(3없음)     새              새              유령 134.4W  드라이기 0.655
oS1nRP   새로 잰다       옛              새              ?
nS1oRP   새로 잰다       새              옛              ?
```

## 판정
```
oS1nRP 가 무너지면   -> 원인은 **2단계 replay 라벨**. 적응만 옛 캐시로 돌리면 산다
nS1oRP 가 무너지면   -> 원인은 **1단계 라벨**. 처방 자체를 다시 설계해야 한다
둘 다 무너지면       -> 라벨 자체가 문제이고 어느 단계든 닿기만 하면 터진다
둘 다 멀쩡하면       -> 두 개가 함께여야 터진다(상호작용) 또는 1단계 시드 요동이다
                       그 경우 1단계를 옛 캐시로 한 번 더 학습해 요동을 재야 한다
```
기준선: 장소 B 오븐 유령 **50W 미만**이면 "멀쩡", 100W 초과면 "무너졌다".
드라이기 F1 **0.90 이상**이면 멀쩡, 0.70 미만이면 무너졌다.

## 이미 아는 것 (해석에 쓴다)
```
1단계 단독 채점 (적응 전, 장소 B)
   cnn_hwB  오븐유령 106.3W  드라이기 0.546   σ(plugged) 0.70~1.00 (구분 못 한다)
   cnn_hwY  오븐유령  75.5W  드라이기 0.632   σ(plugged) 0.92 vs 0.01 (깨끗이 가른다)
```
**1단계는 hwY 가 낫다.** 적응이 hwB 의 106W 는 1.1W 로 지우는데 hwY 의 75W 는
128W 로 키운다. 그래서 원인은 적응 쪽에 있을 가능성이 높다 — 그것이 이 2×2 다.

적응 후 모델은 `on=1 & σ(plugged)≈0.05` 라는, **새 라벨에서 0건인 상태**를
만든다. 두 머리 사이에 구조적 결속이 없어서다. 이것이 다음 처방의 후보다
(`plugged >= on` 을 손실이나 구조로 강제).
