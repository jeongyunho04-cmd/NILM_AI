# 판정 기준 — `ch51 = |I2|` 절대량 채널 (12.164.16~18)

**결과보다 먼저 적는다 (규칙 22). 시드 3개 (규칙 50).**

## 왜
오븐 FAN_LIGHT(14.2W)의 신원은 h2 에만 있다. 15W 로 맞춰 비교하면 h1 은 9종이
모두 64~71mA 라 크기만 말한다. 차수별 전류 예산에서 **h2 에서만 FAN_LIGHT 이
안 묻힌다** — 대표 통전 전력 기준 포트 0.6배, 드라이기 0.7배, 프로젝터 0.1배,
최악(오븐 자기 히터) 2.2배. h3 에서는 프로젝터 28.6배, 에어컨 212배다.

그런데 `ZERO_EVEN_HARMONICS` 가 입력의 짝수차를, `--harm-odd-only` 가 L_harm 의
짝수차를 지운다. 모델은 h1 과 홀수차만 본다. 그래서 조용한 창에서만 잡았다.

## 인공물이 아님을 먼저 확인했다 (12.164.17)
```
                Δ|I1|    Δ|I2|   h2/h1
test_13 프로젝터  176.2    1.75   0.99%     <- h1 이 오븐의 4배인데 h2 는 1/2
test_13 미니PC     86.1    2.94   3.41%
test_7  미니PC     18.5    0.15   0.79%
test_11 오븐       45.1    3.59  **7.97%**
test_12 오븐       44.5    3.29  **7.40%**
```
레인지 전환 인공물이면 전류가 클수록 커야 하는데 정반대다. 실측 비율
(오븐 7.4~8.0% vs SMPS 0.8~3.4%)이 합성 예측(9.33% vs 0.28~1.42%)과 맞는다.

## 처방
```python
EVEN2_CH = 51;  FINE_CHANNELS = 52
out[:, EVEN2_CH] = arcsinh(movavg(|I2|, 30) * CURRENT_SCALE)
```
`ch50` 과 같은 규약으로 뒤에 붙인다. `ZERO_EVEN_HARMONICS` 는 True 로 둔다
(이 채널은 `EVEN_FINE_CHANNELS` 목록에 없다). **차분이 아니라 절대량이다** —
FAN_LIGHT 의 짝수차는 평평해서(6.28/4.31/4.19) `|I2|−|I4|` 가 신호를 지운다
(실측 test_11 에서 3.33−3.41 = −0.08).

`--harm-odd-only` 는 **안 건드린다.** 한 번에 하나만 바꾼다 (규칙 54).

## 자
```
hwZ   대조   새 라벨, 51채널, h2 없음            (있음, seed 0/1/2)
h2    처방   새 라벨, 52채널, ch51=|I2|          seed 0/1/2
```
라벨은 hwZ 와 같다 (`SESSION_PLUGGED_APPS`). 채널 하나만 다르다.

## ① 인과 — 이것이 안 되면 형태가 틀린 것이다
```

                          배경 60~150W (n=272)    hwZ 0.284 -> 올라가야

```
h2 를 주면 시끄러운 창에서도 FAN_LIGHT 을 봐야 한다는 것이 이 처방의 전부다.
**안 움직이면 채널이 안 닿은 것이고, 그때는 `--harm-odd-only` 를 끄는 것이 다음이다.**
