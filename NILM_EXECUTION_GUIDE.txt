[2] 2단계: 데이터 전처리, 세부 상태 라벨링 및 NumPy(.npz) 바이너리 생성
--------------------------------------------------------------------------------
* 동작 내용:
  - data/ 안의 CSV 를 역할별로 분류 (단일 가전 / 무부하 노이즈 / 복합 부하 검증용)
  - 보드 리셋 세션 분리, 패킷 역전 정렬, 60Hz 결측 보간, 음수 글리치 제거
  - 계측 품질 게이팅: pll_locked=0, 측정범위 초과, 전압 클리핑 구간을 무효 처리
    (실측 laptop_charger_2.csv 의 10.27% 가 PLL 미락으로 vrms 0.17V 까지 붕괴해 있었음)
  - P, Q, S, PF, THD_i, 복소수 2채널(Real/Imag), 고조파 비율 추출
  - 히스테리시스 + Dwell-time 상태 머신으로 4-Tier 라벨링 생성
  - 딥러닝 고속 로딩용 .npz 바이너리 압축 저장 및 3패널 진단 차트 PNG 생성

python -m src.run_preprocess_and_label

* 출력 결과 저장 경로:

  - processed_data\labels\         : 가전별 상태 전이 이벤트 JSON 및 요약 메타데이터
  - processed_data\plots\          : 가전별 전력/상태/고조파 프로파일 진단 차트 PNG
  - processed_data\composite_eval\ : 복합 부하 실측(test*, nilm_*) - 검증 전용, 합성 풀 제외

  ** 중요: test 로 시작하는 파일과 nilm_날짜_시각.csv 는 여러 가전이 동시에 돌아간
     녹화이므로 '단일 가전'으로 취급하지 않습니다. 자동으로 composite_eval 로 분리되며
     상태 라벨을 붙이지 않고 세그먼트 풀에도 들어가지 않습니다.

[2-1] 새로 측정한 가전 파일 등록하기 (필수)
--------------------------------------------------------------------------------
파이프라인은 더 이상 파일 이름으로 가전 종류를 추측하지 않습니다.
등록되지 않은 파일이 있으면 즉시 오류를 내고 멈춥니다.

* 새 가전을 측정했다면 src\preprocessing\file_registry.py 의 DEVICE_FILES 에 한 줄 추가:

    "microwave": DeviceSpec("microwave", LoadClass.RESISTIVE, periodic_duty=True),

  - LoadClass : RESISTIVE(히터, I∝V·P∝V²) / SMPS(전자기기, P=일정) / MOTOR(모터, ∝V^0.7)
  - periodic_duty : 서모스탯·릴레이로 주기적 ON-OFF 를 반복하면 True (시간 신축 방식이 달라짐)
  - low_load : 60W 미만 대역에서 동작해 대기전력과 혼동될 수 있으면 True

* 복합 부하 검증용 녹화라면 등록하지 말고 파일명을 test_ 로 시작하게 두면 됩니다.

* 현재 분류 상태만 확인하려면:
python -c "from src.preprocessing.pipeline import PreprocessingPipeline as P; print(P.survey_directory('data'))"


--------------------------------------------------------------------------------
[3] 3단계: 복합 가전 부하 신호 합성(Synthesis) 및 물리적 데이터 증강(Augmentation)
--------------------------------------------------------------------------------
* 동작 내용:
  - 정제된 .npz 데이터로부터 유효 동작 구간(Turn-On 돌입, 정상상태, 종료) 세그먼트 풀 구축
  - 기기 대기전력을 계측 보드 자체 소비와 분리해 추출 (중앙값 기준)
      계측계 소비는 기기 것이 아니므로 합성 전체에서 딱 한 번만 더해집니다.
      전 기기 플러그인 시 대기전력 총합 약 8.2W (이전 구현은 26.7W 로 과대계상)
  - 복소수 고조파 벡터 덧셈(Phasor Addition)으로 다중 가전 동시 가동 신호 합성
  - 실측 기반 전압 환경 샘플링 (221V / 234V 두 콘센트 무리 + 미측정 구간 탐색)
  - 계통 임피던스(Z_grid) 전압 강하를 전류-전압 되먹임 2회 반복으로 수렴
  - 실측 센서와 동일하게 전압을 0.5초(30사이클) 계단으로 양자화
  - 서모스탯 주기 부하(오븐/핫플레이트)는 주기를 보존하는 방식으로 시간 신축
  - 벤치마크 일상 시나리오 생성 및 진단 차트 PNG 저장
  - 대기전력 오탐 방지용 하드 네거티브를 섞은 실시간 배치 제너레이터 벤치마크

# CMD 실행 명령어 (D:\stm project\NILM_AI 경로에서 실행):
python -m src.run_synthesis

* 출력 결과 저장 경로:
  - synthetic_data\scenarios\      : 합성된 복합 부하 시나리오 .npz 파일
  - synthetic_data\plots\          : 복합 부하 분해 정답 및 전압 강하 진단 차트 PNG
  - synthetic_data\synthesis_report.json : 합성 통계, 세그먼트 풀 구성, 배치 벤치마크

* 콘솔에 출력되는 경고를 확인하세요:
  "Low activation diversity" 가 뜨면 그 가전은 독립 활성화 구간이 5개 미만이라
  모델이 해당 파형을 통째로 외울 수 있습니다. 추가 측정이 필요하다는 신호입니다.

[예시 A: 전처리된 개별 가전 .npz 데이터 로드 (초고속 바이너리 읽기)]
```python
from src.preprocessing import load_nilm_npz

# 0.1초 만에 메모리로 즉시 로드
data = load_nilm_npz("processed_data/npz/air_conditioner.npz")

X_harmonics = data["harmonics_ri"]      # Shape: (N, 15, 2) [Real, Imag]
X_power     = data["power_features"]    # Shape: (N, 6) [P, Q, S, PF, V, THD]
y_is_on     = data["is_on"]             # Shape: (N,) [0 or 1]
y_state     = data["state_id"]          # Shape: (N,) [0, 1, 2, 3, 4]
y_power     = data["target_power_w"]    # Shape: (N,) [학습 회귀 타깃. OFF 구간은 0]

# 신규 배열
p_denoised  = data["p_denoised_w"]      # (N,) 계측 바닥만 뺀 전력. OFF 구간도 0 이 아님
                                        #      -> 기기의 진짜 대기전력은 여기서만 알 수 있음
is_valid    = data["is_valid"]          # (N,) 0 이면 품질 게이팅에 걸렸거나 보간된 값
seam        = data["is_segment_seam"]   # (N,) 타임라인 이어붙인 자리

print(f"가전명: {data['metadata']['korean_name']}, 샘플 수: {len(X_harmonics)}")
print(f"녹화 전압 v_ref: {data['metadata']['v_ref_v']}V, 유효 샘플 비율: {data['metadata']['valid_sample_ratio']}")
```

[예시 B: 딥러닝 실시간 훈련용 무한 배치 제너레이터 (On-the-fly Batch Generator)]
```python
from src.synthesis import SegmentPool, NILMBatchGenerator

# 1. 세그먼트 풀 로드
pool = SegmentPool(npz_dir="processed_data/npz")

# 2. 10초(600사이클) 윈도우 배치 생성기 생성
batch_gen = NILMBatchGenerator(
    segment_pool=pool,
    window_size_cycles=600,
    max_concurrent_appliances=3,
    target_mode="seq2point",  # 또는 "seq2seq"
)

# 3. 훈련 루프에서 실시간 배치 호출
X, y_power, y_state, y_on = batch_gen.generate_batch(batch_size=32)
# X shape      : (32, 33, 600)  -> 15 Real + 15 Imag + P, Q, V
# y_power shape: (32, 9)        -> 9개 가전의 정답 유효전력 (꺼졌으면 0)
# y_state shape: (32, 9)        -> 9개 가전의 동작 상태 ID
# y_on shape   : (32, 9)        -> 9개 가전의 On/Off (0 또는 1)
```

[예시 C: 대기전력 오탐을 막는 보조 라벨까지 받기 (권장)]
```python
d = batch_gen.generate_batch_dict(batch_size=32)

d["X"]                # (32, 33, 600)
d["y_on"]             # (32, 9) 활성 여부
d["y_power"]          # (32, 9) 활성 전력 (꺼졌으면 0)
d["y_plugged"]        # (32, 9) 콘센트 연결 여부  <- 신규
d["y_standby_power"]  # (32, 9) 대기 전력        <- 신규 (활성 중이면 0)
d["p_noise_w"]        # (32,)   계측계 자체 소비 (어느 기기 것도 아님)
d["recipe"]           # (32,)   각 윈도우가 어떤 상황으로 생성되었는지

# 물리 보존 법칙이 정확히 성립합니다:
#   관측 P = Σ(활성 전력) + Σ(대기 전력) + 계측계 자체 소비
# y_plugged / y_standby_power 를 보조 태스크로 함께 학습시키면
# 모델이 "전력은 흐르지만 켜진 것은 아니다" 를 명시적으로 표현할 수 있습니다.
```

[예시 D: 대기전력 하드 네거티브 비율 조정]
```python
# 기본 혼합 비율
#   random 0.55 / low_load_among_standby 0.22 / standby_only 0.18 / unplugged_baseline 0.05
batch_gen = NILMBatchGenerator(
    segment_pool=pool,
    recipe_mix={
        "random": 0.40,
        "standby_only": 0.25,             # 활성 0대 + 대기전력만  -> 정답 전부 OFF/0W
        "low_load_among_standby": 0.30,   # 대기 최대 + 저부하 1대 -> 가장 헷갈리는 상황
        "unplugged_baseline": 0.05,       # 아무것도 안 꽂힘
    },
)
```
