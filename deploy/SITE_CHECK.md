# 새 현장에 설치할 때 — 계통 점검

`README.md` 의 부록이다. **설치 장소를 옮길 때 반드시 한 번 돌릴 것.**

---

## 왜 필요한가

`models/adapt_zi_s0.pt` 은 학습 때 **계통 임피던스 보정**을 손실에 넣고 만들었다.
그 보정의 계수는 **학습 장소의 배선값을 담고 있다.**

추론에는 그 값이 안 들어간다 — 보정은 학습 시 손실 항이었고 이 체크포인트는
평범한 CNN 이다. 그래서 **새 현장에서 넣어 줄 인자가 없고**, 대신 그 현장이
학습 장소와 비슷한지 **확인**해야 한다.

그리고 실제로 다르다. 두 장소를 재 봤다:

```
                       R (Ω)   L (µH)   |Z₁| 계단법   V_src,1   V_src,3
학습 장소                1.63     455       2.04       222.7      4.60
다른 장소 (test.csv)     0.51     144      (계단 부족)  234.5      9.83
                        3.2배    3.2배                  +12V     2.1배
```

**임피던스가 3.2배, 배경 3차 전압이 2.1배 다르다.** 이 정도면 학습 때 모델이 본
계통과 다른 계통이고, 배분 성능(특히 SMPS 3종)이 그대로 나온다는 보장이 없다.

## 읽는 법

```
  [진단]
    |I₁| 중앙 4.04 A   폭 12.81 A
    |V₁| 중앙 216.0 V   폭 21.14 V
    ΔI>0.5A 계단 **276개**              <- 100 미만이면 경고가 뜬다

  [① 계통 임피던스]
    |Z₁| = **2.254 Ω**   R² 0.994   (계단 276개)
    학습 장소 2.04 Ω  ->  **1.10배**

  [② 배경 전압]  저부하 하위 5% 창 32개
    V_src,1 221.82V   V_src,3   4.89V   …
    3차 배경 비 **1.06배**

  [판정]
    **같다** (|Z₁| 1.10배, 3차 배경 1.06배) — 측정 폭(±25%) 안입니다.
```

| 판정 | 뜻 | 할 일 |
|---|---|---|
| **같다** | 두 비 모두 1.5배 미만 | `adapt_zi_s0.pt` 을 그대로 쓴다 |
| **주의** | 1.5 ~ 2.0배 | 써 보되 **SMPS 3종 배분을 실제 값과 대조**한다 |
| **다르다** | 2.0배 이상 | 그 현장 자료로 **다시 학습**한다 (아래) |
| **보류** | 계단 부족으로 임피던스를 못 쟀고 배경도 비슷 | 계단이 있는 녹화를 다시 받는다 |

문턱 1.5 / 2.0 은 임의값이 아니다. **`Z` 추정 자체의 폭이 ±25%** 다 — 자 둘(계단법
2.04 vs 비선형적합 1.64)이 25% 다르고, 적합 파일 집합을 11개에서 8개로 바꾸면
1.95 -> 1.63 으로 20% 움직인다. 그보다 작은 차이는 **같다고 봐야 한다.**

## `다르다` 가 나오면 — **재학습이 아니라 재적응**

### 무엇이 라벨을 쓰나

| 단계 | 라벨 | 시간 | 장소가 바뀌면 |
|---|---|---|---|
| ① `Z` 추정 (`run_fit_impedance`) | ❌ **안 씀** | 11초 | **다시 잰다** |
| ② 계수 `A` 적합 (`run_norton_probe`) | ✅ 씀 | 1분 | 기기 구성이 같으면 **그대로** |
| ③ 2단계 적응 (`run_adapt`) | ❌ **안 씀** | 3분 | **다시 돌린다** |

**③ 이 라벨을 안 쓴다는 것이 핵심이다.** 2단계는 원래 `L_cons + L_harm` 만으로 도는
준지도 적응이고 `--w-real-on` 기본이 0 이다. 기기별 정답이 필요 없다.

그리고 **② 를 건너뛸 수 있다.** 물리를 전개하면

```
r  =  −(ΣY)·V_src  +  (ΣY)·(Z·I)
      ────────────    ──────────
      절편이 먹음      **기울기 = ΣY**
```

`Z` 를 독립적으로 추정해서 회귀에 넣었으므로 기울기는 `ΣY` — **기기들의 속성**이지
배선의 속성이 아니다. 같은 기기 9종이면 전이될 것으로 본다.

### 절차 (라벨 불필요, 5분)

```bash
# ① 현장 임피던스 (라벨 0, 11초. 진단이 같이 나온다)
python -X utf8 -m src.run_fit_impedance --stems <현장파일> --out results/z_site.npz

# ② 2단계 적응 — 계수는 그대로, **임피던스만 현장 값으로** (라벨 0, 3분)
#    캐시는 솎은 것을 쓴다 — 20.9GB 가 아니라 2.2GB 다 (아래)
python -X utf8 -m src.run_adapt --init results/cnn_ovh.pt --cache cache/train60_ovh_30k \
    --steps 1000 --seed 0 --harm-weight inv_h2 \
    --harm-offset results/norton_coef.npz \
    --harm-offset-z results/z_site.npz \
    --tag adapt_zi_site --out results

# ③ 배포 묶음에 넣는다
cp results/adapt_zi_site.pt deploy/models/
```

### 현장 키트에 무엇을 들고 가나 — **0.2GB 면 된다** (12.151.3)

②의 `--cache` 가 합성 replay 다 (4.2절, 망각 방지). 학습 저장소의
`cache/train60_ovh` 는 **20.9 GB** 라 그대로면 현장 키트가 21GB 짜리가 된다.
솎아서 쟀다:

```
캐시          용량      합성 MAE(W)      프로젝터W    유령8     F1      판정
300k       20.9 GB   6.474±0.512     -1.63    6.78   0.887    기준
30k         2.2 GB   6.373±0.497     -2.43    6.54   0.886   **같다**
10k         0.7 GB   6.537±0.307     -1.65    6.18   0.888   **같다**
3k         0.22 GB   6.304±0.492     -1.58    7.09   0.888   **같다**
없음 (λ=0)     0 GB   **8.639±0.585**  -0.44    6.39   0.887   ❌ 기기별 33% 악화
```

**replay 는 못 뺀다.** `--lam 0` 은 기기별 MAE 를 33% 올린다. 그런데 **100배 솎아도
차이가 시드 폭 안**이다 — 배분 지표(프로젝터W·유령8·F1)까지 전부 같다. 다양성
천장을 캐시가 아니라 세그먼트 풀이 정해서다 (`traincache` 머리말).

**중요한 것은 replay 의 양이 아니라 존재다.**

⚠ **실측 지표로 고르면 안 된다.** λ=0 도 실측 잔차 9.85W / F1 0.859 로 기준선과
같다. 망각은 기기별 정답이 있는 합성 홀드아웃에서만 보이고, 실측에는 기기별
정답이 없다 (12.4절).

```bash
# 학습 저장소에서 한 번 만들어 키트에 넣는다 (12초)
python -X utf8 -m src.run_subsample_cache --src cache/train60_ovh \
    --dst cache/train60_ovh_30k --n 30000
```

### ⚠ 안 쟀거나 안 되는 것 셋

**① 기울기가 정말 전이되는지 확인 못 했다.** `ΣY` 라는 해석은 물리에서 나오지만
**다른 집 라벨이 없어 실측으로 못 쟀다.**

**② 상수항은 전이가 안 된다.** 배경 `V_src` 효과를 담는데 그 값이 장소 간 2.1배
다르다 (4.60 -> 9.83V). 보정 효과의 **47% 가 상수 몫**이라 작지 않다. `V_src` 를
회귀자로 넣어 완화하려 했으나 적합 파일이 8개뿐이라 실패했다 (`--vsrc-cols`,
1~3열 전부 6.7 -> 7.0/7.1/13.3 으로 나빠짐).

**③ 애초에 재적응이 필요한지도 안 쟀다.** 보정 없는 모델도 장소를 옮기면 나빠질
수 있고, 그러면 이것은 보정이 만든 부담이 아니라 원래 있던 것이다.

### 기기 구성이 다르면

그때는 ②(계수 적합)도 다시 해야 하고 **라벨이 필요하다** — 그 현장에서 사람이
스위치를 적은 기록이 있어야 잔차의 목표를 정할 수 있다.

```bash
python -X utf8 -m src.run_norton_probe --save-coef results/norton_coef_site.npz
```

## 이 도구가 못 하는 것

- **`|Z₁|` 만 낸다.** 차수별 `Z_h = R + j·h·ωL` 의 두 상수를 다 뽑으려면 학습
  저장소의 `src/run_fit_impedance.py` 를 쓸 것 (scipy 가 필요하다. 이 폴더는
  numpy 와 torch 만 쓴다).
- **계통 조건만 본다.** 기기 구성이 다르면 그것대로 별개 문제다 — 학습에 없던
  기기가 있으면 그 전력은 다른 기기로 흩어진다.
- **전압 위상을 안 쓴다.** 펌웨어 v5(2026-09-04)부터 수신기가 `vhdeg1~15` 도
  내보내지만 이 도구는 아직 안 쓴다 — 배경 `V_src` 는 그 집의 상수라 회귀 절편이
  흡수하고, 변하는 부분 `Z·I` 의 위상은 전류 위상이 준다. 전압 파형까지 쓰는 검정은
  학습 저장소 `src/run_circuit_gate_probe.py` (설계 12.184).
